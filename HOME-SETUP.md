# Установка V2 дома (виртуалка на NAS)

Памятка для установки с нуля на домашнюю виртуалку. Схема:

```
клиент ---- VM с V2 ---- роутер ---- интернет
            (NAS)                     |-- аплинк az  -> зарубежный сервер
                                      |-- WARP       -> Cloudflare, российский адрес
                                      `-- байпас     -> домашний провайдер
```

От установки на VPS отличается двумя вещами: сервер стоит за NAT (поэтому нужны проброс портов
и DDNS-имя) и выходит в интернет через домашнего провайдера.

## 0. Что нужно приготовить

- **Виртуалка**: Ubuntu 24.04+, **2 vCPU, 2 ГБ RAM, 20 ГБ диска**. Меньше гигабайта не стоит —
  один kresd со временем занимает ~220 МБ под DNS-кеш.
- **Сеть VM — bridge**, а не NAT: виртуалке нужен собственный адрес в локальной сети.
  Адрес задать **статический** (или закрепить в DHCP роутера), иначе проброс портов уедет.
- **Белый IP** от провайдера. Если серый (CGNAT) — VPN будет работать только внутри дома,
  снаружи подключиться не выйдет никак.
- **Адрес, по которому клиенты будут находить сервер.** Статический белый IP — годится сам адрес.
  Динамический — нужно **DDNS-имя**, иначе при смене адреса профили придётся выдавать заново
  (у Synology своё в DSM → «Внешний доступ» → DDNS, получится `*.synology.me`).
- **Профиль аплинка** до зарубежного сервера (см. шаг 1).

Проверить, что подсети не конфликтуют с домашней сетью: V2 занимает `10.28.0.0/15` (клиенты)
и диапазоны fake IP `10.30.0.0/15` + `198.18.0.0/15`. Обычная домашняя `192.168.x.x` не мешает.

## 1. Профиль аплинка

Аплинк — это туннель до зарубежного сервера, через который пойдёт список `uplink-hosts.txt`.
Профиль берётся с зарубежного сервера, **отдельный для каждой установки**: один и тот же
приватный ключ на двух серверах одновременно работать не будет.

На зарубежном сервере:

```bash
ssh root@ЗАРУБЕЖНЫЙ_СЕРВЕР
/root/antizapret/client.sh 4 nas 3650      # 4 = WireGuard/AmneziaWG, добавить клиента
ls /root/antizapret/client/amneziawg/vpn/  # нужен профиль vpn-*, не antizapret-*
```

Нужен именно **`vpn-*`**: он даёт полный выход в интернет, а `antizapret-*` выпускает только
списки. И именно из папки **`amneziawg`**: профиль должен быть обфусцированным, иначе ТСПУ
режет handshake и туннель не поднимется (симптом — интерфейс UP, но `0 B received`).

Скопировать на виртуалку:

```bash
scp 'root@ЗАРУБЕЖНЫЙ:/root/antizapret/client/amneziawg/vpn/vpn-nas-(*)-am.conf' /tmp/uplink.conf
scp /tmp/uplink.conf root@VM:/root/v2-uplink.conf
```

Без `/root/v2-uplink.conf` установщик остановится с кодом 11.

## 2. Установка

```bash
ssh root@VM
curl -O https://raw.githubusercontent.com/niklzz/az-vpn/main/setup.sh
bash setup.sh
```

Установка идёт 10-20 минут (собирается патченный OpenVPN и AmneziaWG), в конце сервер
перезагрузится сам.

## 3. Ответы на вопросы установщика

Почти везде подходит значение по умолчанию — жать Enter. Осмысленно ответить надо на эти:

| вопрос | ответ | почему |
|---|---|---|
| `Route the AntiZapret list through Cloudflare WARP?` | `y` | ради этого всё и делалось |
| `Nodes:` (узлы Cloudflare) | `HEL` или Enter | вслепую; реальный выбор — шаг 5 |
| `GitHub token:` | Enter | репозиторий публичный, токен не нужен |
| `DNS choice` для **full VPN** | **не 1**, например `4` (Yandex) | при `1` полный VPN получит заграничный DNS при российском выходе |
| `domain name for this OpenVPN server` | внешний IP или DDNS-имя | **важно за NAT** |
| `domain name for this WireGuard/AmneziaWG server` | внешний IP или DDNS-имя | **важно за NAT** |

Про адрес сервера: без него в профиль клиента попадёт локальный адрес виртуалки (`192.168.x.x`),
потому что за NAT сервер своего внешнего адреса не знает. Дома такой профиль работает,
снаружи — нет. При статическом IP можно вписать сам адрес (установщик принимает и его —
проверка идёт через `getent ahostsv4`), при динамическом нужно DDNS-имя, иначе после смены
адреса профили придётся выдавать заново. Забыл указать — не страшно, профили пересоздаются
через `client.sh 7`.

Остальное — `y`/Enter по умолчанию.

## 4. Проброс портов на роутере

Пробросить на адрес виртуалки, **UDP**:

| порт | что |
|---|---|
| `52443` | AntiZapret, WireGuard/AmneziaWG — основной |
| `52080` | полный VPN, WireGuard/AmneziaWG |
| `540`, `580` | резервные для WG/AWG |
| `50080`, `50443` | OpenVPN |
| `80`, `443`, `504`, `508` | резервные для OpenVPN (если включал) |

Минимум для работы — `52443`.

## 5. Выбор узла Cloudflare

После перезагрузки:

```bash
/root/antizapret/warp.sh
```

Скан идёт пару минут и показывает узлы, реально доступные из твоей сети, с задержкой.
Выбрать один или несколько через запятую в порядке предпочтения — список сохранится
и по нему пойдёт автоматическое восстановление, если endpoint перестанет отвечать.

Нужного узла может не быть вовсе: какой PoP обслужит anycast-адрес, решает сеть. С Vpsville,
например, видны только `AMS` и `LHR`, а `HEL` не появляется никогда.

## 6. Профили клиентов

```bash
/root/antizapret/client.sh 4 имя 3650    # WireGuard/AmneziaWG
/root/antizapret/client.sh 1 имя 3650    # OpenVPN
```

Файлы: `/root/antizapret/client/amneziawg/antizapret/` — для трёх путей (то, что нужно обычно),
`.../vpn/` — полный VPN целиком через сервер.

Забрать на свой компьютер:

```bash
scp 'root@VM:/root/antizapret/client/amneziawg/antizapret/antizapret-имя-*.conf' ~/Desktop/
```

Имя файла со скобками длиннее 32 символов ломает импорт на Windows — просто переименуй короче.

## 7. Проверка

```bash
# три пути с самого сервера
curl -s https://api.ipify.org; echo                              # домашний провайдер
curl -s --interface az https://api.ipify.org; echo               # зарубежный сервер
curl -s --interface warp-antizapret https://api.ipify.org; echo  # Cloudflare

# куда поедет домен
dig +short @127.1.1.1 rutracker.org    # 10.30.x или 10.31.x -> WARP
dig +short @127.1.1.1 ya.ru            # реальный адрес -> байпас

# узел Cloudflare и геолокация выхода
curl -s --interface warp-antizapret https://www.cloudflare.com/cdn-cgi/trace | grep -E 'colo|loc|warp'

# состояние
systemctl status antizapret v2-warp-proxy
awg show az                 # handshake с зарубежным сервером
awg show warp-antizapret    # handshake с Cloudflare
```

С клиента после подключения проще всего смотреть по «какой у меня IP»: на `ya.ru` должен быть
домашний адрес, на сайтах из списка — Cloudflare, на сайтах из `uplink-hosts.txt` — зарубежный.

## 8. Настройка списков

```bash
# сайты, которым нужен именно заграничный IP
nano /root/antizapret/config/uplink-hosts.txt
# адреса и подсети туда же
nano /root/antizapret/config/uplink-ips.txt
# свои домены сверх реестра РКН (пойдут через WARP)
nano /root/antizapret/config/include-hosts.txt

/root/antizapret/parse.sh host      # применить домены
/root/antizapret/parse.sh ip        # применить адреса
systemctl restart antizapret        # обязательно после правки uplink-ips.txt
```

Списки в `config/` переживают переустановку. Реестр РКН обновляется сам, раз в сутки ночью.

## Если что-то не работает

**`awg show az` без handshake** — не поднялся аплинк. Проверить, что профиль обфусцированный
(`grep -c '^Jc' /etc/amnezia/amneziawg/az.conf` должно быть 1) и что зарубежный сервер жив.

**WARP без handshake** — `journalctl -u antizapret | grep -i warp`. Ветка чинит себя сама:
при отсутствии handshake зовёт `warp.sh auto` и подбирает другой узел, это занимает полминуты.

**Клиент подключается дома, но не снаружи** — либо не проброшен порт, либо серый IP
у провайдера, либо в профиле локальный адрес вместо DDNS-имени (проверить строку `Endpoint`).

**Клиент не подключается дома по внешнему имени** — роутер не умеет hairpin NAT. Сделать
отдельный профиль с локальным адресом виртуалки или настроить split-DNS.

**Сайты не открываются, DNS не резолвится** — проверить `systemctl status kresd@1 kresd@2`
и что `/etc/resolv.conf` на сервере указывает на рабочий резолвер, а не на что-то локальное.
